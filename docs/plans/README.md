# plans — 開發計劃

這個資料夾放**當前與歷史的開發紀錄**。一件工作一份計劃檔，開發前先寫，開發後回寫結果。

目的是讓 AI agent 與人在同一份契約上工作：動手前先講清楚要改哪些檔案、什麼叫做完；做完後把學到的東西沉澱回主題文件，而不是留在對話紀錄裡蒸發掉。

---

## 檔名規則

```
YYYY-MM-DD-<slug>.md
```

`<slug>` 用 kebab-case 簡短描述，例如：

- `2026-09-02-backlog.md`
- `2026-09-10-admin-order-status.md`
- `2026-09-15-merge-guest-cart.md`

一天內開多份就用不同 slug，不需要編號。

---

## 工作流

```
① 開卡    複製 TEMPLATE.md → 填目標、改動範圍、驗收條件
             │
② 開發    只動「改動範圍」白名單內的檔案
             │  超出範圍 → 停下來更新計劃，不要先斬後奏
③ 驗收    逐條跑驗收條件，把實際輸出貼進計劃的「驗證結果」
             │
④ 回寫    把成果同步到主題文件（見下表）
             │
⑤ 結卡    計劃檔頂端狀態改為「完成」，附完成日期
```

## ④ 回寫對照表

做完之後，**依改動的性質**更新對應文件。這一步是整套文件不腐化的關鍵：

| 這次改了什麼 | 要更新 |
|---|---|
| 新增/移除功能、功能狀態變化 | [FEATURES.md](../FEATURES.md) 的總表與 §7 缺口清單 |
| 新增目錄、新增模組、資料表變動、請求流程變動 | [ARCHITECTURE.md](../ARCHITECTURE.md) |
| 建立新慣例、或釐清了既有慣例、或修掉某項技術債 | [DEVELOPMENT.md](../DEVELOPMENT.md)（含 §15 技術債表） |
| 新增測試檔、補上覆蓋缺口、改動測試設定 | [TESTING.md](../TESTING.md) 的 §3 現況與 §8 缺口 |
| 常用指令、環境需求變動 | 專案根目錄 `CLAUDE.md` |

沒有任何一項需要更新時，在計劃檔的「回寫」欄寫「無」，不要留空。

---

## 狀態標記

計劃檔第一行用引言標註狀態：

```markdown
> 狀態：未開始 | 進行中 | 完成（YYYY-MM-DD） | 擱置（原因）
```

已完成的計劃**保留不刪**，它是這個專案的開發紀錄。
